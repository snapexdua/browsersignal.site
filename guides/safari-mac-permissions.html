Safari on Mac: fix site permissions and website data carefully

A Mac-focused guide to Downloads, Camera, Microphone, autoplay and per-site data controls.

By BrowserSignal EditorialPublished: 9 Nov 2026How-to guide

Safari can remember choices separately for each website, which is helpful until an earlier Deny setting blocks a feature you now need. The fix is often smaller than reinstalling the browser. Apple documents both Websites settings and the Privacy area for managing website data. These controls are powerful, so the goal is to change the smallest necessary permission on the correct domain.

First principle

Site-specific settings are your first stop. Do not enter passwords on unverified pages or bypass browser security warnings.

01 / THE CHECK

Confirm the website and feature

Write down the exact site that fails and whether the missing function is a camera preview, microphone, download, autoplay, pop-up, or page state. A site asking for camera access when it only serves text deserves skepticism. Check the address bar carefully to avoid granting permissions to an imitation domain. Be aware that a meeting app may also require an operating-system permission for Safari itself.

02 / THE CHECK

Use Safari Websites settings

On a Mac, Apple directs users to Safari > Settings > Websites for per-site choices. Categories may include Camera, Microphone, Downloads, Auto-Play, and others depending on Safari version. Find the trusted domain and select the most restrictive setting that still supports your task. If a service needs one-time access, Ask is often preferable to permanent Allow.

03 / THE CHECK

Use targeted website-data removal when needed

For stale sign-ins or site-specific corruption, Apple describes Safari > Settings > Privacy > Manage Website Data. Select the affected website rather than Remove All when possible. Removing site data can sign you out and change website behavior; preserve drafts and verify recovery access first. If the problem is a muted tab or wrong microphone device, deleting data will not solve it.

04 / THE CHECK

Check extensions and cross-app interactions

Safari extensions may have access to selected domains, and some content blockers change page behavior. Temporarily test without a suspected extension or in a separate profile where practical. Do not turn off all privacy protections to force a site to work. When an extension requests unusually broad access, inspect its publisher and whether it is still needed.

05 / THE CHECK

Review after the task

After completing a call or download, revisit the permission and return it to Ask or Deny if continuous access is unnecessary. If an employer manages your Mac, verify any unusual restrictions with IT. If Safari and other browsers all fail on the same trusted site, consider network or service issues rather than repeatedly changing Safari settings.

FIELD EXAMPLE

How this looks in practice

A Mac user cannot download an invoice from a trusted billing portal. Other websites can download PDFs normally. Safari > Settings > Websites shows that this domain’s Downloads permission is set to Deny. Changing only that site to Ask allows the user to approve the invoice download without granting global permission to every website.

TAKE-AWAY

Your short checklist

  1. Verify the exact domain.
  2. Identify the blocked feature.
  3. Inspect Safari > Settings > Websites.
  4. Prefer Ask for temporary access.
  5. Remove site-specific data only when warranted.
  6. Review permissions after use.
