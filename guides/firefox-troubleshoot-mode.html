Firefox Troubleshoot Mode: what it tells you and what it does not

Use Mozilla’s diagnostic mode to narrow down add-on and customization problems.

By BrowserSignal EditorialPublished: 9 Nov 2026How-to guide

Firefox offers Troubleshoot Mode specifically to help identify whether add-ons or certain customizations contribute to a problem. It is a comparison environment, not a promise that every browser bug will be fixed. Mozilla notes that the mode temporarily disables extensions, uses a default theme, and changes some settings including hardware acceleration. Knowing that scope helps interpret results without jumping to conclusions.

First principle

It narrows the cause but does not name it. Do not enter passwords on unverified pages or bypass browser security warnings.

01 / THE CHECK

Start with one reproducible symptom

Choose a failing action—a webpage that freezes, a button that does nothing, or a video that will not play—and record the normal behavior. Check the URL and whether the issue exists in another browser. A vague statement such as “Firefox is weird lately” will not make Troubleshoot Mode informative. Do not test on a sensitive workflow where you may lose unsaved edits.

02 / THE CHECK

Launch the supported diagnostic mode

Mozilla documents the menu route through Help to Troubleshoot Mode, followed by a restart and confirmation. Menus can change between versions; use Mozilla’s current instructions if your interface differs. The purpose is to reopen Firefox in a reduced-customization state. It is not necessary to delete your Firefox profile or all cookies to run this check.

03 / THE CHECK

Interpret a successful test carefully

If the issue disappears, one of the disabled elements is implicated: an extension, theme, acceleration setting, or another customization. It does not identify the exact one. Return to normal mode and isolate extensions individually, then inspect other settings as needed. Avoid re-enabling multiple candidates at once because you will lose the evidence gained.

04 / THE CHECK

Interpret a failed test correctly

If the problem persists in Troubleshoot Mode, extensions are less likely to explain it, but they are not the only possible source of trouble. Investigate the website, network, stored site data, system software, and browser version. If other browsers fail on the same website, the website itself may be responsible. For severe recurring crashes, gather information before considering a full refresh.

05 / THE CHECK

Keep a compact evidence trail

Note the page URL, issue, Firefox version, whether it occurred in normal mode, and whether it occurred in Troubleshoot Mode. Add any specific extension that made the difference during further testing. This is much more useful for a support report than “I tried everything.” Avoid sharing profile directories or logs with account tokens in public forums.

FIELD EXAMPLE

How this looks in practice

A print-preview control does nothing on a web app in normal Firefox but works in Troubleshoot Mode. The user exits the mode and turns extensions off one by one, identifying a script-modifying add-on. Updating that add-on resolves the issue. No mass deletion of bookmarks or saved passwords was needed.

TAKE-AWAY

Your short checklist

  1. Reproduce the normal-mode failure.
  2. Enter Firefox Troubleshoot Mode.
  3. Repeat the exact test.
  4. Interpret the result as narrowing, not proof.
  5. Restore features one at a time.
  6. Document outcome before changing data.
