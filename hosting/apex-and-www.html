Why www works when the bare domain fails

Check the DNS answer, certificate coverage and redirect separately for the two versions of a website address.

Lilik HartantiPublished 27 November 2026

A flyer sends visitors to example.com/menu, but the only address the café tested was www.example.com/menu. The browser treats these as two hostnames. A working menu on one establishes very little about what the other hostname can serve.

Write down two starting URLs

Put https://example.com/menu and https://www.example.com/menu on separate lines. Choose which should appear in the address bar after a visit. Open each directly in a new tab. Note whether the address changes, whether a certificate warning appears and whether the menu page actually loads. Use your own public hostname for the test.

If the direct www visit succeeds and the bare name shows a DNS error, the request for the bare name never reached a redirect rule. A page-level redirect on the working host cannot repair that gap.

Give both names a destination

Add both names to the intended hosting project if the platform requires domain assignments. At the authoritative DNS provider, compare the apex record and the www record with the targets shown for that project. Many setups use an address record at the apex and a CNAME at www. Providers that support apex flattening have another option. Copy the current project instructions before changing anything.

Look for a leftover address for the same web name, including an old IPv6 destination. Different clients can prefer different reachable addresses. Save the previous record and verify its purpose before removing or replacing it.

Trace one redirect all the way to the menu

Expected example with www as the preferred address
StartExpected result
Bare name, /menuValid HTTPS connection, then one redirect to the www name with /menu preserved.
www name, /menuThe menu document opens directly.
Either name, a deliberately missing pageThe final host returns a genuine missing-page response.

Use the Network panel and preserve the log during navigation to see status and Location. If the redirect lands on the homepage, a visitor with a printed deep link loses the page they asked for. If the two names redirect to one another, align the rules at the host and at any forwarding service.

Identify a certificate failure early

An HTTPS request must authenticate the starting name before the browser can read a redirect. When only that name shows a certificate warning, pause there and check certificate coverage in the host’s domain panel. Once coverage is active, retest both starting URLs using a public page and record the final path.
