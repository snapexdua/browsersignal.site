Read a response

A stylesheet returns 200 and the page still looks broken

Read the body type and requested asset path before purging a cache or editing the stylesheet.

Lilik HartantiPublished 27 November 2026

A published recipe page shows its text and links, but the layout vanishes when a reader opens a nested URL. The request for the stylesheet is green in the Network panel. A successful HTTP status tells you an endpoint answered. You still need to know what it sent.

Read the failed asset as a response

In the Network panel reload the public page and select its stylesheet request. Record the requested path, status, Content-Type and the first few visible characters of the response. If the body begins with an HTML document and the response declares text/html, the browser received a page where it expected CSS. Editing the color rules in your original stylesheet cannot change that response.

Run the three sample requests on BrowserSignal to see a stylesheet, an HTML stand-in and an intentionally missing asset. The workbench shows what this host actually returned for your request.

Resolve an address from two different pages

For a document at /recipes/, the relative reference assets/site.css asks for /recipes/assets/site.css. The same reference at the site root asks for /assets/site.css. If only the second file exists, the homepage has styling and the nested document may receive a 404 or a fallback HTML page.

A root-relative link works when the website is published at the domain root. For a site served under a subpath, use the deployment base path or a correctly calculated relative reference. Check the built HTML because a build step may rewrite the original source address.

Distinguish the three common responses

Evidence on the stylesheet request
Observed responseFirst thing to inspect
404 for the requested asset pathFile name, case and published directory. Preserve a real missing-file response while fixing the reference.
200, text/html, a page in the bodyAsset path or a broad rewrite that catches missing assets. Exclude static assets from the fallback.
200, text/css, an older CSS ruleAsset URL used by this HTML, selected deployment and cache headers. Compare the actual rules with the release you intended.

Verify a cache fix across two versions

If old HTML points to yesterday’s asset, keep that older file available long enough for existing pages to load it. Publish changed content under a new versioned asset name and update the HTML reference together. An HTTP no-cache directive asks a cache to revalidate before reuse. A long freshness lifetime on an unchanged filename can keep a previous valid response in use.

Open the previously broken path in a fresh tab. Confirm that the URL resolves to the intended file, the type is appropriate, a distinctive rule from the new version is present and the layout is restored. Record which check changed. A successful hard refresh alone leaves the next visitor’s result uncertain.
