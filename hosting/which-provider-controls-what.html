Which company can fix your website?

Trace a published page back to its registrar, DNS service and web host so a support ticket reaches someone who can act.

Lilik HartantiPublished 27 November 2026

A renewal receipt names one company. The project that published your homepage lives at another. Both can be working while visitors still see a parking page. Before buying a hosting upgrade or transferring the domain, identify which account controls the failing step.

Build a three-line ownership card

Start with a recent registration receipt or the account where you can renew the domain. That is your route to the registrar. In that account, find the delegated nameservers. The service operating those nameservers is where changes to the active DNS zone belong. Finally, open the project that produced your last good deployment and note its public preview and the custom domains attached to it.

One company may fill all three roles. Record the role beside each provider so a later change to hosting does not get mistaken for a transfer of the registration. Keep account invitations and recovery details in your private records, outside your support ticket.

Match the symptom to the owner

Where to take the first question
ObservationCheck first
The renewal date or delegated nameservers are wrong.Registrar account. Confirm the registration and the nameservers you intended to delegate.
The project URL shows the new page. The custom name still opens the parking page.Active DNS provider and host. Compare the public web record with the target the project requests, then check the project’s domain assignment.
Both addresses open the site, but the same article is missing at both.Web host or repository owner. Inspect the files in that production deployment.

A working preview and a parking page

Imagine a club publishes an events page. The registrar’s DNS editor contains a new web record, but the registrar delegates to a different DNS service. That other service still contains the old parking record. Editing the dormant zone again has no public effect. The club compares the delegated nameservers with the DNS service account, opens the active zone and changes just the web record there.

If that active zone already contains the exact project target, a different explanation fits. Check whether the hosting project has claimed this hostname and whether its current production deployment contains the events page. Repeating a DNS edit cannot add a hostname to a project.

Close the ticket with a repeatable result

Use an ordinary HTTPS visit to the exact hostname and a known public path. Record the expected page title, the observed title and the observation time with its time zone. A registrar can investigate a delegation discrepancy. A host can investigate a named deployment serving the wrong document. A report that includes both observations saves each team from asking you to start over.
