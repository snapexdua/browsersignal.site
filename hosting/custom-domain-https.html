Your preview works but the custom domain shows a certificate warning

Separate a working build from hostname assignment and certificate issuance before making changes to the site.

Lilik HartantiPublished 27 November 2026

A project preview can have a valid certificate for the hosting provider’s own name while a newly added custom name is still pending. Testing only the preview proves you can reach that deployment. It leaves the public hostname, its DNS records and its certificate to check.

Record what happened before a page appeared

Write down the exact public hostname, the browser’s error wording and the time. Compare the preview in a separate tab. If the custom address raises a certificate interstitial, stop there and leave the session closed. An owner can investigate from the hosting dashboard. A visitor can report the name and error without sending account information.

Check the spelling carefully. A certificate for www.example.com and a certificate for example.com may have different coverage. A wildcard for one level of subdomains does not by itself cover the bare name.

Read the hosting panel in order

  1. Confirm the hostname belongs to the expected project and production deployment. A verified preview cannot prove this assignment.
  2. Compare the active DNS targets with those displayed by the project. Look at both IPv4 and IPv6 records when present. An old endpoint may present a different certificate.
  3. Read the certificate or issuance state for that hostname. If the host identifies a validation or CAA restriction, use its documented requirements and the organization’s authorized certificate issuers. Removing restrictions blindly can affect other services.

Two observations with different owners

Suppose the bare name reports a healthy certificate and opens the site, while www shows a name mismatch on two devices. Start with the www mapping and its certificate coverage. In a second case, every device shows the correct page except one laptop with an incorrect clock. Correct its date and time through normal settings and retry. Include the scope of the failure when escalating either case.

Redirects happen after the secure connection succeeds. A redirect from a name with an invalid certificate cannot rescue an HTTPS visit to that name. The public check is a direct visit to each advertised hostname followed by one real deep link.

Hand the host evidence it can use

Provide the hostname, deployment identifier, issuer or warning shown, dashboard status, and observations with their times. Leave private keys, cookies and validation tokens out of the message. Ask which validation step is pending. That question is more actionable than requesting a rebuild of an already working site.
