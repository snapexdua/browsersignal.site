The homepage loads but a saved link returns 404

Use direct navigation, a fresh tab and the published file tree to distinguish a missing page from client-side routing.

Lilik HartantiPublished 27 November 2026

A volunteer opens the event list by clicking through the homepage. A bookmark to the same visible address fails the next morning. Those two trips can take different routes through the application. Rebuilding the domain records is a costly detour when the host has already answered the request.

Make three observations on the same deployment

Open the homepage, follow the link inside the site, then paste the final public address into a fresh tab. In the Network panel, look at the document request and its HTTP status. Repeat on the production deployment’s own address if the host provides one. A browser-rendered “page missing” message with HTTP 200 is a different response from an actual HTTP 404.

Write down capitalization, trailing slash and file extension. A link to /Events/ may behave differently from /events/ on a case-sensitive host. Correct internal links as well as old public entry points.

Choose a fix that matches the site

What the published output should contain
Site designWhat to inspect
Static multipage guide at /events/Look for events/index.html in the deployed output, or the documented route equivalent. A copy in the source folder alone does not publish it.
Static page linked as /events.htmlConfirm the exact file is present and the host’s clean-URL settings match the public links.
Client-routed applicationKnown app routes may need a scoped fallback to the app shell. Existing assets and deliberately missing paths still need their own responses.

Worked example from a folder mismatch

A repository contains a built homepage and public/events/index.html. Its publish step copies just the homepage and assets into the output folder. The deployment succeeds because the copied homepage is valid. The deep link returns 404 on both the custom name and the deployment URL. Publishing the missing directory restores the page. Changing a DNS record could only direct all requests somewhere else.

A universal rewrite to the homepage can make the 404 disappear from the Network panel while showing the wrong document. Before adopting a routing change, test one real nested page, one stylesheet and one invented path. For a multipage website the last one should still report a missing page.

Verify what a bookmarked reader will see

Open the saved address directly again and check both the status and the page heading. Use a permanent redirect from an old public path if the article genuinely moved. Preserve the old path when it still identifies the same page. The Response Workbench lets you compare a successful stylesheet request with a deliberately missing file before inspecting your site.
